# SRUI Project Guide

# 1. What This Is

SRUI is a screen-reader-first UI toolkit in C#: a retained semantic tree, keyboard input in, structured accessibility events out, no pixels ever. The design is specified in docs/architecture.md — read it before changing behavior, and keep it current when behavior changes; it is the source of truth, not a summary. This file covers only what that document does not: mechanics, conventions, and the current state of the public surface.

# 2. Layout

The packable libraries and the test suite sit at the repository root; every runnable program lives under samples/ (solution: Srui.slnx, which includes all of them except HelloSrui); native sources and builds under native/.

- Srui — the toolkit. The engine lives in Core/ (namespace Srui.Core, internal): tree, focus/navigation, event queue, the tick end (CoreUi.EndTick: describe the focused widget and the item under its cursor, diff against what the user last heard, append the state events; SruiApp.EndTick runs one per cause — each input, each due ticker, and whatever else an iteration did), the text engine (rope, TextNav, EditorState), plus the SDL3 and prism P/Invoke layers. The public namespace Srui holds SruiApp, Element (fields, bindings) and the Widget base class, the built-in widgets (one file per major widget; each widget object IS its node and carries its own behavior), Dialog, SruiDialogs, SdlHost, MultiAppHost/HostedApp (several apps in one window — architecture.md section 10), Speech, SpeechReader and SpeechRenderer, and the public vocabulary (Field/Fields/Role/Position, InputEvent, AccessibilityEvent, Key/KeyCombo, IReader, IClipboard). SruiApp owns an on-demand SoundManager (SruiApp.Audio) and ticks it from the event loop; hosted apps share the MultiAppHost's manager instead.
- Srui.Generators — the [Field] source generator (netstandard2.0, Roslyn 4.12): a partial [Field] property gets its implementation (stored value or binding, the written-field hook); every [Field] property is registered into the type's generated DescribeFields/TryGet/TrySet, which are generator-only (a hand-written override is a build error): a null read is absence, `[Field(After = ...)]`/`Before` is the key's default place, and a fact a role's word already states is the role's `Implies`. Keys resolve to Srui.Fields by name, else a `{Name}Field` is declared on the type; nested types work when every enclosing type is partial. Referenced as an analyzer (`OutputItemType="Analyzer" ReferenceOutputAssembly="false"`) by Srui itself, the test suite, the samples, and any project consuming Srui by ProjectReference; the Srui package carries it under analyzers/dotnet/cs so PackageReference consumers need nothing.
- Srui.Testing — the consumer test harness, packable, no test-framework dependency (assertions throw plain exceptions). Harness is the abstract base: Spoken/Drain/Expect/ExpectNoSpeech over rendered utterances; Input/Type/Raw for logical input; Press/Down/Up for host-fidelity key simulation (physical phases around the logical input, mapped by the same InputMapper.MapCombo the SDL host uses via InternalsVisibleTo, US-layout TypeChar synthesis); Wait advances the injected clock; Until/UntilHeard run real time (the clock following the wall clock, one iteration per poll) until a condition holds or a timeout names what was waited for — the one sanctioned wait on work outside the engine; Poll.Until is the same wait for a test with no harness at all. TestApp is Harness over one headless SruiApp; TestHost is Harness over a headless MultiAppHost (Tick is one host iteration at the same instant, Wait one at a later one, both through MultiAppHost.TickAt), and a shell's own harness derives from it. Every input method and Wait is a step — discards the previous batch, runs, dispatches — so Expect describes the last step alone, unasserted speech is ignored, and state is assertable right after; Drain is only for batches a programmatic mutation opens (no step precedes them). ComboSpec parses config-form combos plus compact modifier initials ("cas+f4"; the final segment is always the key). Scenario files (RunScenario/RecordScenario) are the plain-text recording format — bare line taps a combo, down/up/type/wait, say asserts the batch's next utterance exactly, nospeech asserts an empty batch, // comments; unasserted batches are flushed and ignored, asserted ones must be asserted completely; the recorder rewrites assertion lines from a real run, and SRUI_RECORD=1 makes RunScenario record instead of assert (the suite-wide re-approval flag). The grammar is deliberately closed — richer assertions are written in C# against the harness, never added as verbs.
- Srui.Tests — xUnit suite, the harness's first consumer. Behavioral tests drive the public surface (TestApp, asserting rendered utterances); TickTests is the tick model's own spec (settled state, ordering, attribution, Suppress/Reread, bindings, custom fields) and TickCauseTests its cause boundaries (an input and a ticker in one iteration read as two ticks); engine invariants (rope, text navigation, tree, tab ring) are property-tested through internals (InternalsVisibleTo). Test classes that nest [Field] types are partial. Headless; no native DLLs needed.
- Srui.Audio — game audio over cosmos.dll: Sound (decoded, streamed, or fed by a managed PullAudioSource — MediaFoundationAudioSource decodes AAC/M4A/M4B; PushAudioSource is the live push-fed ring for network audio: producer thread writes PCM, underruns render silence until Complete(); ProbeDurationMs is the device-free duration read; M4bChapters parses audiobook chapter tables), SoundGroup buses, HRTF pooling, tweens. CreateSound(oneshot: true) hands out a fire-and-forget voice: the caller may drop the reference and the manager disposes the sound on the first Tick after it finishes. Effects: SetFxChain on both Sound and SoundGroup takes an ordered SoundEffect list with repeatable kinds (order-based filters, the multimode biquad, HRTF binauralizer/positional, disperser, reverb, delay, distortion, vocoder, EQ — one node per entry, parameter changes swap in place, chains replay across engine rebuilds); it is the only effect API. Standalone consumers (no SruiApp) drive SoundManager.Tick from their own loop. The device period is chosen at manager creation (SoundManager(periodFrames), 0 = the 128-frame default) and changed via SoundManager.Reconfigure / SruiApp.AudioPeriodFrames, which rebuilds the engine in place preserving the whole soundscape.
- samples/SruiDemo — end-to-end demo: a tab-switched widget gallery exercising every widget type, a custom-authored table widget (TableWidget.cs — the reference for behavior authoring from outside the toolkit: a partial Widget declaring computed [Field]s), all canned and hand-built dialogs, dynamic state, a bound field (the Volume slider is the SFX bus, through Bind), the event stream (with a reviewable event log on Ctrl+L), and sound-augmented lists over Srui.Audio.
- samples/SruiTasks — the object-oriented demo: a small to-do app built as classes rather than a script — an application shell (TaskApp), composite panels as Group subclasses, and built-ins extended by overriding On* methods and ReservesKey (TaskListBox, HistoryEditBox, ConfirmButton), with a state-bearing item type (TaskItem, an Element whose Value is composed from its state) driving the list. Where SruiDemo shows the widget set breadth-first, SruiTasks is the reference for structuring an application around subclassed behavior. Speech only — needs just prism.dll and SDL3.dll.
- samples/MultiAppDemo — the multi-app demo: three apps (Notes, Stopwatch, Inbox) in one window under a MultiAppHost — ctrl+tab switching, inter-app messaging (Notes sends to Inbox), and the background-announcement flag (Inbox speaks arrivals from anywhere; Stopwatch's periodic ticks stay private to it). Speech only — needs just prism.dll and SDL3.dll.
- samples/AudioExample — Srui.Audio walkthrough (no UI stack; needs only cosmos.dll and phonon.dll).
- samples/AudioBench — audio stress benchmark (no UI stack; needs cosmos.dll and phonon.dll): hundreds of looping sources at dozens of 3D positions, reporting load time, HRTF convolver pooling, Tick cost, steady-state allocations, and process CPU. Sources take `--sources/--positions/--seconds`. Reads OGGs from samples/AudioBench/assets/, which is gitignored — bring your own. Runs are audible; never launch one without the user's go-ahead.
- samples/AotDemo — the Native AOT canary: the smallest windowed app (name field, shout toggle, greet button), published with PublishAot to prove the toolkit and Srui.Testing compile and run ahead-of-time. `--headless` replays an embedded scenario (prints the transcript, exits nonzero on the first divergence) so the AOT binary is verifiable in a terminal; `--headless --record` prints a fresh recording for pasting back after an intentional behavior change.
- native/ — everything native: cosmos/ (vendored miniaudio + cosmos DSP nodes + Steam Audio glue + the xiph opus stack; decodes wav, flac, mp3, vorbis, and opus, UTF-8 filenames throughout), phonon/ (Steam Audio binaries), prism/ (vendored Prism), prebuilt/SDL3.dll, and build-native.ps1 which stages every DLL into native/out/.
- samples/HelloSrui — consuming srui as published packages (two PackageReferences, resolved from artifacts/ via a local nuget.config until they are on nuget.org), deliberately outside the solution.
- templates/ — the dotnet new template pack (Srui.Templates, packable, in the solution; the template content projects are not). srui-app creates a windowed greeter — Program.cs runs the same Ui.Build the test project drives headless — plus a test project with utterance assertions and a recorded scenario, passing from the first build. sourceName is "MyApp", so the app name renames through file names, namespaces, and the scenario alike. Template content pins Srui/Srui.Testing versions literally; see section 5.
- The tag rust-era marks the last commit of the retired Rust implementation the engine was ported from; the tag handle-era marks the last commit of the handle-addressed public API (NodeId + Ui facade + wrapper registry) before widgets became their own nodes.

# 3. Building and Running

Native first, managed second — but the native step is rare: run native/build-native.ps1 when native sources change or on a fresh clone; it stages prism.dll, SDL3.dll, cosmos.dll, and phonon.dll into native/out/, from which the csproj files copy them. The DLLs are optimized C/C++ regardless of the .NET configuration. The script's toolchain paths (cmake, ninja, clang-cl, vcvars, midl) are overridable via env vars documented at its top.

- C# demo: `dotnet run --project samples/SruiDemo`
- Object-oriented demo: `dotnet run --project samples/SruiTasks`
- Multi-app demo: `dotnet run --project samples/MultiAppDemo`
- Audio walkthrough: `dotnet run --project samples/AudioExample`
- Audio stress bench: `dotnet run --project samples/AudioBench -c Release` (audible; ask first)
- NuGet packages: `./pack.ps1` (add `-VersionSuffix rc.1` for a prerelease); output in artifacts/. Pushing is deliberately manual — nuget.org versions cannot be withdrawn once pushed, only unlisted.
- Flat binary drop, for consumers who cannot take a NuGet dependency: `./dist.ps1`
- Bleeding-edge consumer refresh (this machine consumes SRUI from artifacts/ via the user-level `srui-local` package source, not nuget.org): `./refresh.ps1` (add `-SkipNative` when native sources are unchanged) — packs, purges the global NuGet cache copies, and reinstalls the template pack, so `dotnet new srui-app` anywhere on the machine and every consumer project's next build pick up the new bits. Run it after any SRUI change a consumer project should see.
- Native AOT check: `dotnet publish samples/AotDemo -c Release -r win-x64`, then run `samples/AotDemo/bin/Release/net10.0/win-x64/publish/AotDemo.exe --headless` (exit 0 = pass). SruiDemo also carries PublishAot, so `dotnet publish samples/SruiDemo -c Release -r win-x64` is the full-surface compile check (verify by running the published exe; `dotnet run` on it stays JIT). The publish needs the VS Installer directory on PATH — the BuildTools vcvars chain calls a bare vswhere.exe, and its error output otherwise corrupts the linker path the ILCompiler captures. It is on the user PATH on this machine; a shell whose inherited environment predates that addition needs `$env:PATH += ';C:\Program Files (x86)\Microsoft Visual Studio\Installer'` first.

The demos speak through Prism (the running screen reader, or platform TTS as fallback) and need a real window with keyboard focus, so they are not useful headless.

# 4. Testing

`dotnet test Srui.Tests` — everything runs fully headless. Behavioral tests build widgets in a TestApp (the Srui.Testing harness — see its entry in section 2), push input, and assert the utterances the recording reader hears; scenario files freeze whole exchanges and are run from tests. Engine invariants are property-tested with seeded-random generators. New behavior is expected to arrive with its invariants encoded the same way. SruiDemo is the end-to-end check for anything the headless suite cannot see (real window, real speech); AotDemo's embedded scenario is the ahead-of-time check.

# 5. Packaging

Four packages: Srui (prism.dll, SDL3.dll) and Srui.Audio (cosmos.dll, phonon.dll) carry their native binaries under runtimes/win-x64/native/, which the host resolves by name — consumers copy nothing; Srui.Testing is managed-only; Srui.Templates is content-only (the dotnet new pack). Shared metadata lives in Directory.Build.props; per-project description, IsPackable, and native items live in the csproj files. The two native-bearing projects fail the pack outright if native/out is missing, since a None item with a nonexistent path would otherwise contribute nothing and ship a package that compiles and then dies on the first P/Invoke.

- Version is VersionPrefix in Directory.Build.props, currently 0.x deliberately: the surface still has open items in section 7, and a published version can only be unlisted, never withdrawn.
- Srui depends on Srui.Audio unconditionally, because SruiApp.Audio is typed SoundManager. phonon cannot be split out either: cosmos.dll imports phonon.dll directly (CMake links phonon.lib), so Steam Audio is mandatory for cosmos to load at all. Making it optional is a native change — delay-load plus a runtime fallback — not a packaging one.
- Windows-only is reported by Srui.Audio/build/Srui.Audio.targets (warning SRUI0001) rather than by a -windows TFM or SupportedOSPlatform, because it reflects build coverage rather than design: SDL3 is cross-platform and prism carries Orca and speech-dispatcher backends. Srui always depends on Srui.Audio, so one copy of the targets file reaches every consumer.
- GenerateDocumentationFile is on for all three, so the .xml ships; CS1591 is suppressed in Srui and Srui.Audio while the vocabulary files (Input.cs, SoundFx.cs, Events.cs, Key.cs) remain undocumented (filling those in is the outstanding documentation debt); Srui.Testing is fully documented and carries no suppression.
- The template content (templates/srui-app/**/*.csproj) pins Srui and Srui.Testing versions literally; bumping VersionPrefix must update them in the same change, or the template births projects against the previous release.
- A repack at an unchanged version must purge the global NuGet cache (%USERPROFILE%\.nuget\packages\srui*): the cache wins over the local feed, and same-version-different-bits fails at run time with MissingMethodException, not at restore. `./refresh.ps1` does the purge; do it by hand only when packing outside that script.
- Licensing: Apache-2.0 in LICENSE, vendored terms in THIRD-PARTY-NOTICES.md, both shipped inside each package. A new vendored native component needs an entry there, and its licence text placed beside it.

# 6. Rules

- One SruiApp, one thread. Nothing may introduce cross-thread access to an app or its engine.
- Steady-state audio paths (Tick, SetListener, spatialization updates) allocate nothing; keep them that way. The same holds for the idle event loop: empty SdlHost.Pump and engine drain batches are a shared read-only list, so an idle app allocates nothing per iteration.
- The engine (Srui.Core) is sans-IO: no platform calls, no clock, no clipboard — hosts inject those. P/Invoke lives only in the designated interop files (Sdl3.cs, PrismNative.cs, User32.cs, and Srui.Audio's bindings); strings cross as UTF-8, native booleans marshal as one byte, and constants/struct layouts are transcribed from the vendored native headers, not from documentation.
- Behavior lives in the widget object. Engine dispatch calls the focused widget's OnInput; the engine itself owns only tree, focus, navigation, shortcuts, layers, the tick end, and the text primitives. Don't put widget-kind knowledge back in the engine.
- No prose in the engine or the widgets. Every spoken fact is a typed field; every word is the reader's (SpeechRenderer's tables). The remaining exceptions are the editor's own action contexts ("blank", "N characters") and refusal announcements; do not add to them.
- Widgets never announce state and never check focus. Change a field (or let a binding change it) and the tick end reads the difference; Suppress a field for the tick when an action event of your own is the better voice, Reread one when it should be said unchanged. Action events (typing, a cursor move, an edge, a refusal) are emitted as they happen. There are no silent setter variants and no programmatic-versus-user distinction: do not reintroduce either.
- Inside OnInput, mutate only your own widget's state; anything that touches other widgets or the tree (opening dialogs, removing widgets) must be deferred via Post/PostChanged so it runs at drain time, outside dispatch. The built-ins model this. Private state a computed field reads must be followed by Touch() so the loop's next tick end describes it.
- Widgets are designed to be subclassed from application assemblies: override the On* methods and keep the base call so composition subscribers still fire; author new widget kinds from the Widget base (SruiDemo's TableWidget is the reference) as partial classes declaring [Field] properties. Items are Element subclasses the same way (SruiTasks' TaskItem).
- Vendored code (native/cosmos, native/phonon, native/prism) is snapshot plus documented local patches. Any change to vendored sources must be recorded in native/PATCHES-cosmos.md or native/PATCHES-prism.md so it survives a snapshot update; prefer additive wrapper files (the cosmos_extra.c pattern) over edits to upstream files.
- A behavior change that alters user-visible UX should be reflected in SruiDemo where the demo exercises it.
- Docs are Wikipedia-esque prose with numbered headings and no historical narrative; history belongs in commit messages. docs/architecture.md must always describe the present design.
- Commit as often as possible: each coherent change gets its own commit as soon as the tests are green. Never let unrelated work pile up in the working tree.

# 7. The Public Surface As Of Now

One object per widget: SruiApp and the Widget classes are the whole public story (no handles; the engine facade is internal). Everything a reader can know is a field (architecture.md section 4.2): Field&lt;T&gt; keys compared by reference, the core set in Fields (Name, Role, Description, Shortcuts, Disabled, Required, Warning, WithHelp, MultiSelect, Count, Position, Filter, Value, SelectedText, Checked, Expanded, ChildCount, Level, ReadOnly, Multiline, Password, Number, Min, Max, Unit), Role a registry (Role.Button … Role.ShortcutField, Role.None, `new Role("table")`), Position an (Index, Total) record. Element is the base of widgets and items: `[Field]` properties (partial ones generated — stored or bound; ordinary ones registered as computed), DescribeFields/Describe, TryGet/TrySet by key, Bind(field, get, set?)/Unbind/IsBound. Widget adds Suppress(fields)/Reread(fields)/RereadItem() (per tick), Touch(), CurrentItem (the item under the cursor, whose fields are the item scope), AnnounceBoundary/Announce/Promulgate for action events, Post/PostChanged/PostActivated, ReservesKey, Focus/IsFocused/Remove, Hidden, KeyHelp/AnnounceHelp (nonstandard-key documentation: "with help", framework-shown on F1, F1 reserved via the ReservesKey base call while set), and the events Changed/Activated. Everything in the widget set is usable: Label, Group (role settable: `new Group(parent, null, new Role("console"))`), Button, CheckBox (Checked), EditBox single/multi-line (Value the current line, SelectedText, ReadOnly, Multiline, Password — a masked field: stars for every spoken form, no copy or cut, "protected" on focus; Text, CursorPosition, Selection, SelectAll, Length; UTF-16 code-unit positions, setters clamp and snap backward onto grapheme cluster boundaries; pure position queries Previous/NextWordStart, Previous/NextWordExtent, WordAt, LineStartAt/LineEndAt/LineTextAt, LineCount, LineColumnAt/PositionAt; the Move* family runs the same path as the key it names; InsertText speaks like typing, ReplaceRange is the silent splice; multi-level undo — ctrl+z, redo on ctrl+y or ctrl+shift+z, EditBox.Undo/Redo, UndoMemory; the editing paths Suppress the line and selection fields, the Text setter reads the new line), ListBox&lt;T&gt;/FilterListBox&lt;T&gt; (T : Element; Items stored or BindItems-bound, SelectedItem/SelectedIndex, RemoveAt/Insert/Add/SetItem on stored items — the cursor follows its item by identity and lands on the survivor when it goes; MultiSelect with Enter or toggleWithSpace, IsChecked/SetChecked/CheckedItems/ItemToggled/CanToggle over the item's Checked field; FilterListBox: Filter (null for none), Score (default fuzzy over Value), Ranked (the pool's order is the rank and Score only excludes — for a list over an engine's output), Results (a read-only view over the list's own buffers, fresh on each read outside a tick-end description and shared by the reads inside one), OnFilterChanged, ReportEmptyResults, SelectedResultIndex), the non-generic ListBox/FilterListBox over ListItem (Value, Checked; string overloads), TreeView&lt;T&gt; (T : TreeNode&lt;T&gt; — Value, Expanded, Checked, ChildCount, Level, Children, Checkable, Parent; Roots/SetRoots/BindRoots, SelectedNode/SelectNode, Refresh, NodeToggled, IsChecked/SetChecked/CheckedNodes/NodeChecked, numbered counts siblings, activateItems claims Enter; branch-local navigation, Right opens-and-enters, Left collapses — read as "collapsed" — then jumps to parent, outward-scanning typeahead), Slider (Number, Min, Max, Unit, Step, LargeStep; writes clamp), TabControl (tabs are items; ActiveIndex/ActiveTab/Tabs, AttachPanels), ShortcutField (Combo — its own ComboField key — Value the display form, Echo), role-less CustomWidget. Layers/dialogs, primary/cancel routing (Activated is a Widget-level event, so any widget can be a target), tickers, focus control, announcements, and the host clipboard (injectable on headless apps via SruiApp.SetClipboard) are as before. Disabled widgets stay tabbable ("unavailable") but are inert; only hidden widgets leave navigation.

Readers: one call per tick (IReader.OnTick with the tick's list — announcements and action events in order, then FocusArrived with its FocusCause and context entries, ItemArrived, and FieldValue entries; every event carries its Source widget, and only the settled widget's events survive). SpeechReader (Prism) is installed by the windowed constructor and renders through SpeechRenderer.Default: RenderTick(events, verbosity) → utterances, Register&lt;T&gt;(field, render, after) and SetRoleName for a program's own fields and roles, RenderAction for a single action event, SpeakChar; ReadoutContext gives a field renderer the widget, the verbosity, whether the readout is an arrival, and Get(field) over the batch then the widget. SruiApp.Headless() plus HandleInput/HandleKey/DispatchEvents/SetNow make any host loop (or test) a first-class driver (a tick is one cause — an input, a ticker, or the program's mutation between them — so DispatchEvents ends the pending tick and then runs each due ticker as a tick of its own; Tick/TickAt end a tick per input and skip the description on a clean engine), and SruiApp.Tick runs one real-time event-loop iteration (Run is Tick in a loop; false once Quit or the window closed) so one host loop can drive several apps — at most one windowed, the rest headless with input forwarded. Apps read time back via SruiApp.Now (engine clock, frame-coherent ulong ms) and PreciseNow (live sub-microsecond TimeSpan on the same epoch; follows the engine clock when headless).

Multi-app hosting (architecture.md section 10): MultiAppHost owns the one window, one shared SpeechReader, and one shared SoundManager across hosted apps created via Add(name), at startup or from running handlers (HostedApp: Name, App, IsActive, AnnouncesInBackground, Activated/Deactivated, Send/MessageReceived — drain-time mailbox, dropped once closed). One app is active (all input; ctrl+tab / ctrl+shift+tab cycling via nullable NextAppCombo/PreviousAppCombo, matched ahead of the app and hard-reserved inside hosted apps — bind dialogs query SruiApp.ReservedReasonFor, which folds host reservations into the framework's); the rest run muted except opted-in Announce events. Activation announcements are graded by Activate's SwitchAnnouncement parameter: NameAndFocus (default and combo behavior: name, then focus-with-context), FocusOnly (task-list picks), Silent; HostedApp.Name is mutable and read at announcement time. Deactivation runs the app's FocusLost and clears SruiApp.IsForeground. HostedApp.Close (idempotent, drain-time; a hosted app's own Quit becomes Close next tick) activates and announces the neighbor when the active app closes, silently otherwise; IsClosed/Closed and MultiAppHost.AppsChanged feed task-list UIs over MultiAppHost.Apps. MultiAppHost.Headless() plus HandleInput/HandleKey/DispatchEvents mirror the SruiApp seams. System-wide hotkeys: MultiAppHost.SystemHotkeys (ISystemHotkeys — Register(id, combo) answers null or the spoken refusal, Unregister(id); null headless), HotkeyPressed(id) on the app thread from the pump, and RaiseWindow; KeyCombo carries a Win modifier ("windows"/"win+", Mods.Win, Key.Win in the physical stream) whose combos are always RawKey (architecture.md sections 6.1 and 10). MultiAppHost.AppFailed receives (HostedApp, Exception) when an app's own code throws during input, key, message, or tick delivery, so a shell can close and report the one app rather than die; unset, the exception propagates as before.

The bind-dialog toolkit is complete: KeyCombo is public with display/config forms, TryParseConfig, and ReservedReason (framework-reserved combos with spoken refusals); Widget.ReservesKey is a public virtual every widget kind implements. Logical inputs carry physical provenance (the combo that actually produced them, including shift+printables), so shortcut matching and ShortcutField capture are exact; synthetic inputs without provenance fall back to the canonical reverse map. Input handlers match by physical intent with InputEvent.Is(KeyCombo)/Is(Key) (provenance first, canonical fallback) and by typed character with IsChar(char) (full-codepoint comparison, astral-safe).

Game-style input rides the physical key stream (architecture.md, section 6.4): Widget.BindKey attaches press/repeat/release handlers to any widget, focus-scoped, with SruiApp.UnhandledKey and SruiApp.FocusLost as the app-level hooks. Typing, list typeahead, and filter queries are astral-plane-safe (surrogate pairs are one character throughout).

Known deliberate limits:

- No braille or platform (UIA) reader ships yet; the reader seam is where they attach, and the typed fields are what they would map.
- The remaining prose inside the toolkit: the editor's action contexts (EditorState's "blank", "N characters", the spoken forms of TextNav/Selection/UndoRedo), the TreeView's non-checkable refusal, and the refusals inside SruiDialogs. A translation layer would have to reach these; nothing else.
- FilterListBox computes its results on every read outside a tick-end description (the reads inside one share a computation, into buffers reused across computations), so a read from program code is always fresh and a pool of thousands costs one filter per tick. A pool of millions is the source's problem, not the widget's: cap what the source hands over, as Lightspeed's search providers do.
- Widget shortcut lists have no public getter (announcements speak the first shortcut; a bind dialog that wants to enumerate them will motivate the accessor).
- Tree insertion is append-only on the public surface (the engine supports indexed insertion; surface it when a consumer appears).
