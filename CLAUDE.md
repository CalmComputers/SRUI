# SRUI Project Guide

# 1. What This Is

SRUI is a screen-reader-first UI toolkit in C#: a retained semantic tree, keyboard input in, structured accessibility events out, no pixels ever. The design is specified in docs/architecture.md — read it before changing behavior, and keep it current when behavior changes; it is the source of truth, not a summary. This file covers only what that document does not: mechanics, conventions, and the current state of the public surface.

# 2. Layout

.NET projects at the repository root (solution: Srui.slnx); native sources and builds under native/.

- Srui — the toolkit. The engine lives in Core/ (namespace Srui.Core, internal): tree, focus/navigation, event queue and coalescing, the text engine (rope, TextNav, EditorState), plus the SDL3 and prism P/Invoke layers. The public namespace Srui holds SruiApp, the Widget base class and built-in widgets (one file per major widget; each widget object IS its node and carries its own behavior), Dialog, SruiDialogs, SdlHost, MultiAppHost/HostedApp (several apps in one window — architecture.md section 10), Speech and SpeechReader, and the public vocabulary (InputEvent, AccessibilityEvent, WidgetInfo, Key/KeyCombo, IReader, IClipboard). SruiApp owns an on-demand SoundManager (SruiApp.Audio) and ticks it from the event loop; hosted apps share the MultiAppHost's manager instead.
- Srui.Testing — the consumer test harness, packable, no test-framework dependency (assertions throw plain exceptions). TestApp wraps a headless SruiApp plus a RecordingReader: Spoken/Drain/Expect/ExpectNoSpeech over rendered utterances; Input/Type/Raw for logical input; Press/Down/Up for host-fidelity key simulation (physical phases around the logical input, mapped by the same InputMapper.MapCombo the SDL host uses via InternalsVisibleTo, US-layout TypeChar synthesis); Wait advances the injected clock. ComboSpec parses config-form combos plus compact modifier initials ("cas+f4"; the final segment is always the key). Scenario files (RunScenario/RecordScenario) are the plain-text recording format — bare line taps a combo, down/up/type/wait, say asserts the batch's next utterance exactly, nospeech asserts an empty batch, // comments; unasserted batches are flushed and ignored, asserted ones must be asserted completely; the recorder rewrites assertion lines from a real run, and SRUI_RECORD=1 makes RunScenario record instead of assert (the suite-wide re-approval flag). The grammar is deliberately closed — richer assertions are written in C# against the harness, never added as verbs.
- Srui.Tests — xUnit suite, the harness's first consumer. Behavioral tests drive the public surface (TestApp, asserting rendered utterances); engine invariants (rope, text navigation, tree, tab ring) are property-tested through internals (InternalsVisibleTo). Headless; no native DLLs needed.
- Srui.Audio — game audio over cosmos.dll: Sound (decoded, streamed, or fed by a managed PullAudioSource — MediaFoundationAudioSource decodes AAC/M4A/M4B; PushAudioSource is the live push-fed ring for network audio: producer thread writes PCM, underruns render silence until Complete(); ProbeDurationMs is the device-free duration read; M4bChapters parses audiobook chapter tables), SoundGroup buses, HRTF pooling, tweens. CreateSound(oneshot: true) hands out a fire-and-forget voice: the caller may drop the reference and the manager disposes the sound on the first Tick after it finishes. Effects: SetFxChain on both Sound and SoundGroup takes an ordered SoundEffect list with repeatable kinds (order-based filters, the multimode biquad, HRTF binauralizer/positional, disperser, reverb, delay, distortion, vocoder, EQ — one node per entry, parameter changes swap in place, chains replay across engine rebuilds); it is the only effect API. Standalone consumers (no SruiApp) drive SoundManager.Tick from their own loop. The device period is chosen at manager creation (SoundManager(periodFrames), 0 = the 128-frame default) and changed via SoundManager.Reconfigure / SruiApp.AudioPeriodFrames, which rebuilds the engine in place preserving the whole soundscape.
- SruiDemo — end-to-end demo: a tab-switched widget gallery exercising every widget type, a custom-authored table widget (TableWidget.cs — the reference for behavior authoring from outside the toolkit), all canned and hand-built dialogs, dynamic state, the event stream (with a reviewable event log on Ctrl+L), and sound-augmented lists over Srui.Audio.
- SruiTasks — the object-oriented demo: a small to-do app built as classes rather than a script — an application shell (TaskApp), composite panels as Group subclasses, and built-ins extended by overriding On* methods and ReservesKey (TaskListBox, HistoryEditBox, ConfirmButton), with a state-bearing IListItem type (TaskItem) driving the list item operations. Where SruiDemo shows the widget set breadth-first, SruiTasks is the reference for structuring an application around subclassed behavior. Speech only — needs just prism.dll and SDL3.dll.
- MultiAppDemo — the multi-app demo: three apps (Notes, Stopwatch, Inbox) in one window under a MultiAppHost — ctrl+tab switching, inter-app messaging (Notes sends to Inbox), and the background-announcement flag (Inbox speaks arrivals from anywhere; Stopwatch's periodic ticks stay private to it). Speech only — needs just prism.dll and SDL3.dll.
- AudioExample — Srui.Audio walkthrough (no UI stack; needs only cosmos.dll and phonon.dll).
- AudioBench — audio stress benchmark (no UI stack; needs cosmos.dll and phonon.dll): hundreds of looping sources at dozens of 3D positions, reporting load time, HRTF convolver pooling, Tick cost, steady-state allocations, and process CPU. Sources take `--sources/--positions/--seconds`. Reads OGGs from AudioBench/assets/, which is gitignored — bring your own. Runs are audible; never launch one without the user's go-ahead.
- AotDemo — the Native AOT canary: the smallest windowed app (name field, shout toggle, greet button), published with PublishAot to prove the toolkit and Srui.Testing compile and run ahead-of-time. `--headless` replays an embedded scenario (prints the transcript, exits nonzero on the first divergence) so the AOT binary is verifiable in a terminal; `--headless --record` prints a fresh recording for pasting back after an intentional behavior change.
- native/ — everything native: cosmos/ (vendored miniaudio + cosmos DSP nodes + Steam Audio glue + the xiph opus stack; decodes wav, flac, mp3, vorbis, and opus, UTF-8 filenames throughout), phonon/ (Steam Audio binaries), prism/ (vendored Prism), prebuilt/SDL3.dll, and build-native.ps1 which stages every DLL into native/out/.
- samples/HelloSrui — consuming srui as published packages (two PackageReferences, resolved from artifacts/ via a local nuget.config until they are on nuget.org), deliberately outside the solution.
- templates/ — the dotnet new template pack (Srui.Templates, packable, in the solution; the template content projects are not). srui-app creates a windowed greeter — Program.cs runs the same Ui.Build the test project drives headless — plus a test project with utterance assertions and a recorded scenario, passing from the first build. sourceName is "MyApp", so the app name renames through file names, namespaces, and the scenario alike. Template content pins Srui/Srui.Testing versions literally; see section 5.
- The tag rust-era marks the last commit of the retired Rust implementation the engine was ported from; the tag handle-era marks the last commit of the handle-addressed public API (NodeId + Ui facade + wrapper registry) before widgets became their own nodes.

# 3. Building and Running

Native first, managed second — but the native step is rare: run native/build-native.ps1 when native sources change or on a fresh clone; it stages prism.dll, SDL3.dll, cosmos.dll, and phonon.dll into native/out/, from which the csproj files copy them. The DLLs are optimized C/C++ regardless of the .NET configuration. The script's toolchain paths (cmake, ninja, clang-cl, vcvars, midl) are overridable via env vars documented at its top.

- C# demo: `dotnet run --project SruiDemo`
- Object-oriented demo: `dotnet run --project SruiTasks`
- Multi-app demo: `dotnet run --project MultiAppDemo`
- Audio walkthrough: `dotnet run --project AudioExample`
- Audio stress bench: `dotnet run --project AudioBench -c Release` (audible; ask first)
- NuGet packages: `./pack.ps1` (add `-VersionSuffix rc.1` for a prerelease); output in artifacts/. Pushing is deliberately manual — nuget.org versions cannot be withdrawn once pushed, only unlisted.
- Flat binary drop, for consumers who cannot take a NuGet dependency: `./dist.ps1`
- Bleeding-edge consumer refresh (this machine consumes SRUI from artifacts/ via the user-level `srui-local` package source, not nuget.org): `./refresh.ps1` (add `-SkipNative` when native sources are unchanged) — packs, purges the global NuGet cache copies, and reinstalls the template pack, so `dotnet new srui-app` anywhere on the machine and every consumer project's next build pick up the new bits. Run it after any SRUI change a consumer project should see.
- Native AOT check: `dotnet publish AotDemo -c Release -r win-x64`, then run `AotDemo/bin/Release/net10.0/win-x64/publish/AotDemo.exe --headless` (exit 0 = pass). SruiDemo also carries PublishAot, so `dotnet publish SruiDemo -c Release -r win-x64` is the full-surface compile check (verify by running the published exe; `dotnet run` on it stays JIT). The publish needs the VS Installer directory on PATH — the BuildTools vcvars chain calls a bare vswhere.exe, and its error output otherwise corrupts the linker path the ILCompiler captures. It is on the user PATH on this machine; a shell whose inherited environment predates that addition needs `$env:PATH += ';C:\Program Files (x86)\Microsoft Visual Studio\Installer'` first.

The demos speak through Prism (the running screen reader, or platform TTS as fallback) and need a real window with keyboard focus, so they are not useful headless.

# 4. Testing

`dotnet test Srui.Tests` — everything runs fully headless. Behavioral tests build widgets in a TestApp (the Srui.Testing harness — see its entry in section 2), push input, and assert the utterances the recording reader hears; scenario files freeze whole exchanges and are run from tests. Engine invariants are property-tested with seeded-random generators. New behavior is expected to arrive with its invariants encoded the same way. SruiDemo is the end-to-end check for anything the headless suite cannot see (real window, real speech); AotDemo's embedded scenario is the ahead-of-time check.

# 5. Packaging

Four packages: Srui (prism.dll, SDL3.dll) and Srui.Audio (cosmos.dll, phonon.dll) carry their native binaries under runtimes/win-x64/native/, which the host resolves by name — consumers copy nothing; Srui.Testing is managed-only; Srui.Templates is content-only (the dotnet new pack). Shared metadata lives in Directory.Build.props; per-project description, IsPackable, and native items live in the csproj files. The two native-bearing projects fail the pack outright if native/out is missing, since a None item with a nonexistent path would otherwise contribute nothing and ship a package that compiles and then dies on the first P/Invoke.

- Version is VersionPrefix in Directory.Build.props, currently 0.x deliberately: the surface still has open items in section 7, and a published version can only be unlisted, never withdrawn.
- Srui depends on Srui.Audio unconditionally, because SruiApp.Audio is typed SoundManager. phonon cannot be split out either: cosmos.dll imports phonon.dll directly (CMake links phonon.lib), so Steam Audio is mandatory for cosmos to load at all. Making it optional is a native change — delay-load plus a runtime fallback — not a packaging one.
- Windows-only is reported by Srui.Audio/build/Srui.Audio.targets (warning SRUI0001) rather than by a -windows TFM or SupportedOSPlatform, because it reflects build coverage rather than design: SDL3 is cross-platform and prism carries Orca and speech-dispatcher backends. Srui always depends on Srui.Audio, so one copy of the targets file reaches every consumer.
- GenerateDocumentationFile is on for all three, so the .xml ships; CS1591 is suppressed in Srui and Srui.Audio while the vocabulary files (Input.cs, SoundFx.cs, Events.cs, Key.cs) remain undocumented (filling those in is the outstanding documentation debt); Srui.Testing is fully documented and carries no suppression.
- The template content (templates/srui-app/**/*.csproj) pins Srui and Srui.Testing versions literally; bumping VersionPrefix must update them in the same change, or the template births projects against the previous release.
- A repack at an unchanged version must purge the global NuGet cache (%USERPROFILE%\.nuget\packages\srui*): the cache wins over the local feed, and same-version-different-bits fails at run time with MissingMethodException, not at restore. `./refresh.ps1` does the purge; do it by hand only when packing outside that script.
- Licensing: Apache-2.0 in LICENSE, vendored terms in THIRD-PARTY-NOTICES.md, both shipped inside each package. A new vendored native component needs an entry there, and its licence text placed beside it.

# 6. Rules

- One SruiApp, one thread. Nothing may introduce cross-thread access to an app or its engine.
- Steady-state audio paths (Tick, SetListener, spatialization updates) allocate nothing; keep them that way. The same holds for the idle event loop: empty SdlHost.Pump and engine drain batches are a shared read-only list, so an idle app allocates nothing per iteration.
- The engine (Srui.Core) is sans-IO: no platform calls, no clock, no clipboard — hosts inject those. P/Invoke lives only in the designated interop files (Sdl3.cs, PrismNative.cs, and Srui.Audio's bindings); strings cross as UTF-8, native booleans marshal as one byte, and constants/struct layouts are transcribed from the vendored native headers, not from documentation.
- Behavior lives in the widget object. Engine dispatch calls the focused widget's OnInput; the engine itself owns only tree, focus, navigation, shortcuts, layers, coalescing, and the text primitives. Don't put widget-kind knowledge back in the engine.
- Inside OnInput, mutate only your own widget's state (the label follows by itself: its derived fields are functions of that state); anything that touches other widgets or the tree (opening dialogs, removing widgets) must be deferred via Post/PostChanged so it runs at drain time, outside dispatch. The built-ins model this.
- Widgets are designed to be subclassed from application assemblies: override the On* methods and keep the base call so composition subscribers still fire; author new widget kinds from the Widget base (SruiDemo's TableWidget is the reference). A programmatic state setter must speak exactly what the equivalent user-driven change speaks — share the emission path, and keep it silent when the widget isn't focused.
- Vendored code (native/cosmos, native/phonon, native/prism) is snapshot plus documented local patches. Any change to vendored sources must be recorded in native/PATCHES-cosmos.md or native/PATCHES-prism.md so it survives a snapshot update; prefer additive wrapper files (the cosmos_extra.c pattern) over edits to upstream files.
- A behavior change that alters user-visible UX should be reflected in SruiDemo where the demo exercises it.
- Docs are Wikipedia-esque prose with numbered headings and no historical narrative; history belongs in commit messages. docs/architecture.md must always describe the present design.
- Commit as often as possible: each coherent change gets its own commit as soon as the tests are green. Never let unrelated work pile up in the working tree.

# 7. The Public Surface As Of Now

One object per widget: SruiApp and the Widget classes are the whole public story (no handles; the engine facade is internal). Everything in the widget set is usable: all built-in kinds (Label, Group, Button, CheckBox, EditBox single/multi-line with read-only, ListBox, FilterListBox, Slider, TabControl, ShortcutField, role-less CustomWidget), behavior authoring by subclassing Widget (OnInput, role text, ValueText/StateText overrides — the label's derived fields are functions of widget state, pulled at announcement time, never stored — Announce/AnnounceItem/Promulgate, Post/PostChanged/PostActivated, ReservesKey; Widget.SetNameSilently, ListBox.SetItemsSilently/SelectSilently, FilterListBox.SetItemsSilently/SelectedResultIndex, and EditBox.SetTextSilently for subclass input handlers that reshape base-owned state; FilterListBox.OnFilterChanged runs before the results report so live-source subclasses can swap items for the new filter), layers/dialogs, primary/cancel routing (Activated is a Widget-level event, so any widget can be a target), tickers, focus control, announcements, and the host clipboard (injectable on headless apps via SruiApp.SetClipboard). List widgets are generic over their items (ListBox&lt;T&gt;/FilterListBox&lt;T&gt;, T : class, IListItem — typed Items/SelectedItem/Results, no casts in subclasses; the non-generic ListBox/FilterListBox are the plain-IListItem forms carrying the string convenience overloads). ListBox supports multi-select (multiSelect: true — "multi select list" role, per-item checks spoken as "checked"/silence on navigation, Enter toggles or toggleWithSpace moves it to Space at the cost of multi-word typeahead; IsChecked/SetChecked/CheckedItems/ItemToggled, SetCheckedSilently for bulk sweeps whose caller announces the outcome; the CanToggle override refuses user toggles per item — announce the reason from the override, SetChecked is never refused). An item's Text is the spoken/matched line, read live so mutated item state needs no sync call; FilterScore ranks against a filter query, null excludes, default is the built-in fuzzy match. Item operations own the structural announcements: RemoveAt speaks the survivor the selection lands on (or "empty"), Insert/Add speak only the transition out of empty, SetItem (replace an item object) is silent. TreeView&lt;T&gt; (T : TreeNode&lt;T&gt;, self-typed; non-generic TreeView over plain TreeNode) is the expandable list: branch-local Up/Down with silent wrap (boundary words are a list's; the tree's numbered position betrays the seam), Right opens-and-enters in one gesture, Left collapses then jumps to parent, outward-scanning typeahead that prefers visible nodes and reveals collapsed matches; Roots/SetRoots, SelectedNode/SelectNode, Refresh, NodeToggled, numbered counts siblings, activateItems claims Enter; multiSelect checks with Space per TreeNode.Checkable (leaves default yes, branches opt in; non-checkable refuses with a word; IsChecked/SetChecked/CheckedNodes/NodeChecked) (architecture.md section 5). TabControl.AttachPanels (one panel per tab) gives the control its panels: the active one shows, the rest hide and leave navigation, synced on every switch. Widget state is properties throughout: Name, Description, KeyHelp (nonstandard-key documentation: announces "with help", framework-shown on F1, F1 reserved via the ReservesKey base call while set; AnnounceHelp = false drops the spoken state, keeping F1 and the reservation, for apps where help is ubiquitous), Hidden, Disabled, Required, Warning, ListBox.Items/SelectedIndex, TabControl.ActiveIndex, Slider.Value, ShortcutField.Combo (a KeyCombo?), CheckBox.Checked, EditBox.Text/ReadOnly plus an editing surface (CursorPosition, Selection, SelectedText, SelectAll, Length; UTF-16 code-unit positions, setters clamp and snap backward onto grapheme cluster boundaries — never inside a surrogate pair, combining sequence, or CRLF), pure position queries (Previous/NextWordStart, Previous/NextWordExtent, WordAt, LineStartAt/LineEndAt/LineTextAt, LineCount, LineColumnAt/PositionAt with 0-based lines and code-unit columns), announced movement (the Move* family runs the same path as the key it names — MoveWordRight speaks like ctrl+right — silent unfocused), and programmatic editing (InsertText speaks like typing and replaces the selection; ReplaceRange is the silent splice that maps cursor and selection through the edit; both ignore ReadOnly, which guards user input). Focused-state setters speak like the equivalent user action; other label properties and state flags changed on the focused widget speak the delta alone (LabelChange/StateChange events), never a full re-announcement. Disabled widgets stay tabbable ("unavailable") but are inert; only hidden widgets leave navigation.

Readers: structured accessibility events (AccessibilityEvent with Widget references and WidgetInfo snapshots; Focused additionally carries its FocusCause — user navigation, shortcut jump, programmatic, recovery, layer restore, re-announcement) reach any number of attached IReader implementations; SpeechReader (Prism) is installed by the windowed constructor, and SruiApp.Headless() plus HandleInput/HandleKey/DispatchEvents/SetNow make any host loop (or test) a first-class driver, and SruiApp.Tick runs one real-time event-loop iteration (Run is Tick in a loop; false once Quit or the window closed) so one host loop can drive several apps — at most one windowed, the rest headless with input forwarded. Apps read time back via SruiApp.Now (engine clock, frame-coherent ulong ms) and PreciseNow (live sub-microsecond TimeSpan on the same epoch; follows the engine clock when headless). SpeechRenderer is the public reference rendering.

Multi-app hosting (architecture.md section 10): MultiAppHost owns the one window, one shared SpeechReader, and one shared SoundManager across hosted apps created via Add(name), at startup or from running handlers (HostedApp: Name, App, IsActive, AnnouncesInBackground, Activated/Deactivated, Send/MessageReceived — drain-time mailbox, dropped once closed). One app is active (all input; ctrl+tab / ctrl+shift+tab cycling via nullable NextAppCombo/PreviousAppCombo, matched ahead of the app and hard-reserved inside hosted apps — bind dialogs query SruiApp.ReservedReasonFor, which folds host reservations into the framework's); the rest run muted except opted-in Announce events. Activation announcements are graded by Activate's SwitchAnnouncement parameter: NameAndFocus (default and combo behavior: name, then focus-with-context), FocusOnly (task-list picks), Silent; HostedApp.Name is mutable and read at announcement time. Deactivation runs the app's FocusLost and clears SruiApp.IsForeground. HostedApp.Close (idempotent, drain-time; a hosted app's own Quit becomes Close next tick) activates and announces the neighbor when the active app closes, silently otherwise; IsClosed/Closed and MultiAppHost.AppsChanged feed task-list UIs over MultiAppHost.Apps. MultiAppHost.Headless() plus HandleInput/HandleKey/DispatchEvents mirror the SruiApp seams.

The bind-dialog toolkit is complete: KeyCombo is public with display/config forms, TryParseConfig, and ReservedReason (framework-reserved combos with spoken refusals); Widget.ReservesKey is a public virtual every widget kind implements. Logical inputs carry physical provenance (the combo that actually produced them, including shift+printables), so shortcut matching and ShortcutField capture are exact; synthetic inputs without provenance fall back to the canonical reverse map. Input handlers match by physical intent with InputEvent.Is(KeyCombo)/Is(Key) (provenance first, canonical fallback) and by typed character with IsChar(char) (full-codepoint comparison, astral-safe).

Game-style input rides the physical key stream (architecture.md, section 6.4): Widget.BindKey attaches press/repeat/release handlers to any widget, focus-scoped, with SruiApp.UnhandledKey and SruiApp.FocusLost as the app-level hooks. Typing, list typeahead, and filter queries are astral-plane-safe (surrogate pairs are one character throughout).

Known deliberate limits:

- Speech verbosity is not yet reader-configurable; SpeechRenderer has a single rendering. The parameter's home is SpeechReader when it comes.
- No braille or platform (UIA) reader ships yet; the reader seam is where they attach.
- Widget shortcut lists have no public getter (announcements speak the first shortcut; a bind dialog that wants to enumerate them will motivate the accessor).
- Tree insertion is append-only on the public surface (the engine supports indexed insertion; surface it when a consumer appears).
